1. **Branch inventory** – the `branch-inventory.csv` and `branch-inventory.md` must be available (they are generated by the previous step).

3. **CI environment** – all merges will be executed through `git merge --no-ff` to preserve history and will be verified by the existing GitHub Actions pipeline.

## Expected Outcomes
* All branches that are already merged into `main` are documented.
* All remaining branches are either merged, marked as conflicting, or slated for deletion.
* No accidental deletion or merge of incomplete work occurs.

## Caveats
* The plan assumes that all pending PRs are still relevant; PRs that have been superseded by newer branches should be handled during the *Consolidate duplicates* step.
* Since the GitHub API data is not available, the plan relies on the branch inventory only. Once PR and issue data are incorporated, steps 4‑6 may need adjustment.
